# Senses Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the webcam classifier into `senses`, a local background service that keeps a searchable text history of screens, speech and presence and exposes it to agents over MCP.

**Architecture:** One asyncio daemon process. Sources (screen, camera, audio) are auto-detected adapters; processors turn frames and audio into `Event`s on an in-process bus; a SQLite FTS5 store, a presence state machine, a rules engine and a watch registry consume them. A priority-queued model client talks to `llama-server` (Gemma 4 E4B) for presence, summaries and transcription; RapidOCR reads screen text. An MCP server (streamable HTTP, localhost) and a small CLI sit on top.

**Tech Stack:** Python ≥ 3.11, stdlib `unittest`, `mcp==2.3.0` (`MCPServer`), `rapidocr==3.10.0` + `onnxruntime==1.31.1`, `opencv-python==5.0.0.93`, `numpy`, `soundcard==0.4.6`, `pysilero-vad==3.4.0`, `mss==10.2.0`, `jeepney` (D-Bus), llama.cpp `llama-server`.

**Spec:** `docs/superpowers/specs/2026-10-28-senses-design.md`

## Global Constraints

- Text only in storage: never write frames, screenshots or audio to disk except transient files in a private temp dir that are deleted immediately after reading.
- Nothing hard-coded about monitors, desktop environments, devices or models; every source backend is probed, logged, and overridable in `config.toml`.
- A missing or failing capability turns that source off and shows in `status()`; it never crashes the daemon.
- Capture (screen, audio, scene) only while present and not paused; exception: screen watches registered by an agent may capture while away, evaluated in memory, only firing events stored.
- Model requests: images before text, `chat_template_kwargs: {"enable_thinking": false}`, GBNF `grammar` for terse outputs.
- Default retention 30 days; default screen interval 2 s; activity summary at most every 30 s; scene note every 60 s; presence 1 Hz near transitions, 0.3 Hz when stable.
- Default rule: on `presence.away`, after `10s`, run `@media.pause` and `@screen.lock`.
- `wait_for` default timeout 60 s, hard cap 90 s; watch default ttl 1 h, capped at 30 min while away.
- Resource targets: model VRAM ≤ 8 GB; daemon average CPU ≤ 15% of the machine.
- MCP and control HTTP bind to `127.0.0.1` only. Default port 8765.
- Linux (Wayland via portals or commands, X11) is the v1 target; no Windows/macOS-specific code beyond what the chosen libraries give for free.
- No password or secret redaction in v1.
- Tests: stdlib `unittest`, runnable offline with `python -m unittest discover -s tests` (no model server, camera, screen or audio device needed; hardware goes behind fakes).

## Review Focus

1. **Model server down or slow during presence checks** → presence must hold its last state; a model error never produces `away` and therefore never locks the screen. (Task 6 test `test_model_error_holds_state`.)
2. **Search queries with punctuation, quotes or diacritics** (`server.js`, `"C++"`, `pastrare` vs `păstrare`) → no FTS syntax error; diacritic-insensitive match. (Task 2 tests.)
3. **A device vanishes mid-run** (webcam unplugged, screenshot command starts failing, audio device removed) → that source goes `off` with the error in `status()`, the daemon keeps running and re-probes every 60 s. (Task 11 test `test_failing_source_turns_off_and_recovers`.)
4. **Static screen with a ticking clock or blinking cursor** → no event spam: changes below `min_change` are ignored and unchanged lines are not re-stored. (Task 5 test `test_tiny_change_ignored`.)
5. **Owner returns, or pauses, during the 10 s away delay** → pending lock/pause actions are cancelled; with `pause --all` presence rules do not fire at all. (Task 9 test `test_return_cancels_pending`, Task 11 test `test_pause_all_suspends_rules`.)

  - `MssBackend()` — one frame per physical monitor, names `monitor-1..N` (mss indices ≥ 1).
  - `CommandBackend(command: str)` — `command` contains `{path}`; runs `shlex.split(command.format(path=...))` with a 10 s timeout, path inside a `tempfile.mkdtemp(prefix="senses-")` dir with mode 0700; reads with `cv2.imread`, deletes the file in `finally`; one frame named `desktop`.
  - `PortalScreenshotBackend()` — `org.freedesktop.portal.Screenshot.Screenshot("", {"interactive": False, "handle_token": ...})` via `jeepney`, waits for the `Response` signal (5 s), reads the returned `file://` URI, deletes the file; one frame named `desktop`.
  - `KNOWN_COMMANDS = [("spectacle", "spectacle -b -n -f -o {path}"), ("grim", "grim {path}"), ("gnome-screenshot", "gnome-screenshot -f {path}"), ("screencapture", "screencapture -x {path}")]`.
  - `detect_screen(cfg: ScreenConfig, env=os.environ, which=shutil.which, probe: bool = True) -> tuple[ScreenBackend | None, list[str]]` — returns the backend and human-readable log lines ("portal: skipped (…)", "spectacle: ok"). `cfg.backend` in `{"mss", "portal", "command"}` forces one (`command` uses `cfg.command`). Auto order: Wayland session (`WAYLAND_DISPLAY` set) → ScreenCast (Task 16, if available) → portal screenshot → first `KNOWN_COMMANDS` entry found by `which`; otherwise → `mss` → commands. With `probe=True` each candidate must complete one `capture()` within 5 s returning ≥ 1 non-empty frame; a candidate that fails or times out (for example, a portal that wants a dialog every call) is skipped with the reason logged.
  - `Camera(cfg: CameraConfig)` with `read() -> Frame` (name `camera`; opens lazily; `SourceError` when it cannot open or read; device `cfg.device` or first index 0..3 that opens), `close()`.

  - `OcrLine(text: str, x: int, y: int)`; Protocol `OcrEngine.read(image) -> list[OcrLine]`; `RapidOcrEngine()` (lazy `rapidocr.RapidOCR()`; box top-left as `x, y`).

Algorithm for `process`: keep per screen the last image and a list of `OcrLine` in screen coordinates. Find `changed_region`; none → `None`. Otherwise take the band `y-16 .. y+h+16` across the **full width** (so text lines are not cut), clamp, OCR the band, translate `y` by the band offset, replace stored lines whose `y` lies inside the band with the new ones, keep the rest, sort by `(y, x)`. Emit `Event(frame.ts, f"screen:{frame.name}", "screen.text", "\n".join(new_lines(old_band_texts, new_band_texts)), {"screen": frame.name, "busy": <bool>})`, or `None` if nothing new. Token bucket per screen with capacity and refill `ocr_per_minute` per minute; when empty, skip OCR, keep the *previous* image as reference (so the change accumulates) and set `busy=True` on the next emitted event.

  - `Daemon(config: Config, store: Store, client: ModelClient, screen: ScreenBackend | None, camera: Camera | None, audio: tuple[AudioStream | None, AudioStream | None], ocr: OcrEngine, clock=time.time, sleep=asyncio.sleep)`. Constructor does no I/O; sources may be `None`.
  - `async run() -> None` — starts the loops below; returns when `stop()` is called.
  - `stop()`, `pause(duration: float | None = None, all: bool = False) -> None`, `resume() -> None` (both publish `capture.paused` / `capture.resumed`, the former with `meta={"all": all, "until": ...}`; a duration schedules an automatic resume).
  - `status() -> dict` — keys: `presence` (`"present"`/`"away"`), `capture` (`CaptureState` value), `paused_until`, `sources` (`{name: {"backend": str, "state": "on"|"off", "error": str|None}}` for `screen`, `camera`, `mic`, `desktop`), `model` (`{"url", "healthy"}`), `watches` (count), `lock_held_by_watch` (bool), `exclusions` (`"active"`/`"unavailable"`).
  - `now(sources: list[str] | None = None) -> dict` — `{"presence": ..., "screens": {name: {"text": "\n".join(lines), "summary": latest summary text or None}}, "recent_speech": [last 10 speech events from the store within 5 min], "scene": latest camera.scene text or None}`.
  - `async look(source: str, prompt: str | None = None) -> str` — fresh capture of `camera` or `screen[:name]`; with a prompt: `describe` at `INTERACTIVE` priority (max_tokens 160); without: screen → current OCR text from a fresh `ScreenTextProcessor` pass plus a summary; camera → `scene_note`.
  - `async ask(source: str, questions: dict) -> dict` — fresh capture, `client.ask(..., priority=INTERACTIVE)`; returns `local_decide`'s result.
  - Attributes used by the MCP layer: `store`, `watches: WatchRegistry`, `bus: EventBus`.

Loops (each catches and logs its own exceptions; a source that raises `SourceError` three times in a row is marked `off`, publishes `source.off`, and is re-probed every 60 s, publishing `source.on` when it works again):
1. **Store writer:** subscribes to the bus; writes every event to the store unless `event.meta.get("store") is False`; also feeds `watches.on_event`, `rules.on_event`, publishes `watch.fired` events (stored) for watches that fire.
2. **Presence:** every `fsm.interval(now)`; probability from a camera frame via `client.ask` with the `PresenceConfig.question` as a binary question at `PRESENCE` priority; without a camera, `idle_probability(idle_seconds())`; transitions publish `presence.present` / `presence.away`. Runs in `ACTIVE` and `PAUSED`, not in `PAUSED_ALL` (then `rules.suspended = True`). On entering `away`, `watches.cap_ttl(1800, now)`.
3. **Screen:** every `screen.interval`; runs when (`present` and `ACTIVE`) or (`away` and not `PAUSED_ALL` and not `PAUSED` and `watches.has_screen_watch()`). Frames go through `ScreenTextProcessor`; events captured while away get `meta["store"] = False`. Summaries via `Throttle(summary.min_interval)` only while present and `ACTIVE`. Question watches on screens are evaluated here every 2 s at `WATCH` priority.
4. **Camera extras:** scene note every `summary.scene_interval` while present and `ACTIVE`; question watches on `camera` every 2 s at `WATCH` priority (also while away, unless `PAUSED_ALL`).
5. **Audio:** one thread per `AudioStream`; blocks are dropped unless present and `ACTIVE`; otherwise `Segmenter` → `SpeechProcessor`.
6. **Housekeeping:** every 0.5 s `rules.tick` (publish returned events) and `watches.expire`; `rules.hold("@screen.lock")` while `watches.has_screen_watch()` and away, `rules.release(...)` otherwise; every hour `store.purge(now - retention_days * 86400)`.
